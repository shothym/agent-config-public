# Research workflow

多段リサーチを行う。最低でも「検索 → 精読 → クロスチェック」を 1 周し、
不足や矛盾があれば追加検索を行う (上限 3 周程度)。
各ステップが完了してから次のステップに進むこと。

## 並列実行のルール（ステップ 2 / 4 で厳守）

ステップ 2 (WebSearch) と ステップ 4 (WebFetch) は **必ず 1 つのアシスタントメッセージ内に N 個の tool_use ブロックを並べて発行する**こと。これが Claude における並列実行の唯一の方法であり、これを守らない限り並列化されない。

- ✅ 正: 1 メッセージに `WebSearch` × N 個 (または `WebFetch` × N 個) の tool_use を同時に含める
- ❌ 誤: 1 メッセージにつき 1 呼び出しを発行 → 結果を見る → 次の 1 呼び出し（これは直列）
- ❌ 誤: 「まず A を検索します」と書いて 1 件だけ呼び、結果を受けて次を呼ぶ
- 検証項目が N 個あるなら、ステップ 2 の最初のメッセージ内に **同時に N 個** の WebSearch を発行する。途中で結果を読んで考えず、まず全件を投げる。
- ステップ 4 も同様。精読対象 URL が M 個あるなら、1 メッセージ内に **同時に M 個** の WebFetch を発行する。
- 「1 件ずつ結果を確認しないと次のクエリが決められない」と感じても、ステップ 2/4 ではそれは禁止。クエリ/URL の調整が必要なら次の周回（ステップ 5 → 2 へ戻る）で行う。


1. **リサーチ計画**
   - ユーザーの質問を「答えるために確認すべき事実」のリストに分解する。
   - 比較・推奨判断系の質問では、判断軸 (性能 / 事例 / サポート状況 / コスト等) を先に決める。
   - 1 質問につき検証項目を 2〜5 個立てる。
   - 各検証項目は互いに独立した「並列で検索可能なタスク」として扱う。

2. **各項目を並列にWebSearch (一次検索)**
   - **1 つのアシスタントメッセージに、検証項目数ぶんの WebSearch tool_use ブロックを同時に並べて発行する。** これが並列実行の唯一の方法。1 メッセージ 1 呼び出しは禁止。
   - 検証項目ごとに 1〜6 語の具体的なクエリを **英語** で実行する。
   - 日本国内固有の話題 (国内法・国内サービス等) のみ日本語クエリを許可。
   - 全件の結果が揃ってからステップ 3 に進む。

3. **精読URLの候補選定**
   - 結果から上位 5〜10 件を選ぶ。
   - 優先度: 公式ドキュメント > 一次情報 (論文 / ベンダー発表) > 新しい日付 > 権威ドメイン
   - クロスチェックのため、各検証項目につき最低 2 ソース確保する。

4. **精読URLに対して並列にWebFetch (精読)**
   - **1 つのアシスタントメッセージに、対象 URL 数ぶんの WebFetch tool_use ブロックを同時に並べて発行する。** これが並列実行の唯一の方法。1 メッセージ 1 呼び出しは禁止。
   - URL を読む。prompt には検証項目に基づく **具体的な質問** を入れる ("summarize" は禁止)。
   - 事実・数値・原文の該当箇所をメモする。
   - 全件の結果が揃ってからステップ 5 に進む。

5. **クロスチェック & 追加検索**
   - 精読結果を突き合わせ、次のいずれかに該当する場合は手順 2 に戻る:
      - 検証項目が埋まらない
      - ソース間で主張が矛盾する
      - 一次情報で裏が取れない
   - 反復は上限 3 周。それでも未解決の項目は「確認できず」として残す。

6. **結果の受け渡し（中間成果物として親へ返す）**
   - 翻訳・要約せず原語のまま、抽出結果のみを返す（全文は破棄）。
   - 各主張に出典 URL を併記。確証・矛盾の主張には直接引用（原則 1 文）を必須とする。未確認・未発見は「N/A」。
   - ソース間の矛盾は両論を明示。本文未確認は「本文未確認」、検証できなかった項目は「確認できず」と明記。
   ※ ユーザー向けの日本語整形・引用まとめは呼び出し元（親）が担う。


# 出力フォーマット

中間成果物として親へ返す。Markdown 固定スキーマで簡潔に。
ラベル(キー)は英語で固定し、値(主張・数値・引用など)は **原語のまま** 残す(翻訳しない)。
ユーザー向けの日本語整形は親が行う。

```markdown
## Research findings (intermediate, original language)

### Findings per item
- **<verification item>**
  - claim: <fact / conclusion, original language>
  - evidence: <figures / conditions, original language>
  - source: <URL>
  - quote (1 sentence; required when confirmed/conflicting, else "N/A"): "<original quote>"
  - status: confirmed / conflicting (cite both) / body-unverified / not-found

### Unresolved
- <item>: not-found (reason)
```
